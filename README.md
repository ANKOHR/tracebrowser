# TraceBrowser

Reliable, replayable browser automation with evidence for every action.

[Live dashboard](https://tracebrowser-web.vercel.app) · GitHub publication target: `ANKOHR/tracebrowser`

TraceBrowser is a deterministic browser-runtime and trace dashboard for operational workflows that need bounded execution, explicit assertions, recoverable checkpoints and honest failure states. It is not a generic autonomous browser agent and it does not require an LLM or credentials.

## What is implemented

- Typed, versioned browser task definitions backed by SQLAlchemy models.
- Playwright actions for navigation, clicks, form filling, selection, waits, extraction, downloads, assertions, screenshots and checkpoints.
- Explicit selector strategies: CSS, role, text, label and test IDs, with task-authored fallbacks.
- Per-step screenshots, bounded DOM evidence, selector used, outputs, latency, retry count and request log.
- Bounded action/page/runtime policies, domain allowlists, download controls and approval-gated external submission.
- Durable run states including `WAITING_FOR_APPROVAL`, `SUCCESS` and typed failure classes.
- Idempotent run submission, immutable task-version hashes, checkpoint resume and replay from the beginning.
- Simple screenshot-difference scoring for controlled UI drift checks.
- Local synthetic fixtures for CRM data entry, portal table extraction and explicit fallback recovery.
- FastAPI API, SQLite local fallback and PostgreSQL-ready SQLAlchemy configuration.
- A static-first Next.js dashboard seeded from the verified showcase artifacts.

## Verified locally

The local verification path uses synthetic websites in `demo_sites/` and a locally installed Chromium/Chrome executable. It does not contact third-party sites, use credentials, bypass CAPTCHAs or claim autonomous selector healing.

```powershell
py -3.13 -m pip install -e ".[dev]"
py -3.13 -m ruff check tracebrowser scripts tests
py -3.13 -m pytest
py -3.13 scripts/run_showcase.py
py -3.13 -c "from tracebrowser.cli import main; main()" benchmark --output reports/tracebrowser-benchmark.json
```

The current local run has 40 pytest cases, three Playwright showcase scenarios and a 50-case deterministic contract benchmark. The benchmark is explicitly synthetic; its measurements are not production reliability claims.

## Run the API

```powershell
$env:TRACEBROWSER_ARTIFACT_ROOT = "apps/web/public/artifacts"
py -3.13 -m uvicorn tracebrowser.main:app --reload
```

The API uses SQLite by default. A PostgreSQL URL can be supplied through `DATABASE_URL`; install the optional driver with `pip install -e ".[postgres]"`. The optional `tracebrowser.worker` module provides a Dramatiq boundary, but a queue-backed deployment is not claimed or verified by the local evidence.

## Dashboard

```powershell
cd apps/web
npm install
npm run dev
```

The dashboard deliberately labels the data as controlled synthetic fixtures. It shows the CRM approval trace, portal extraction and broken-UI fallback evidence generated by `scripts/run_showcase.py`.

## Truth boundary

The repository proves a local deterministic runtime over controlled fixtures. It does not claim live third-party automation, production authentication, CAPTCHA bypass, arbitrary selector healing, real customer outcomes, or a verified queue-backed deployment. See [`docs/evidence.md`](docs/evidence.md) for the evidence ledger.
